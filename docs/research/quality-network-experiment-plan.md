# 품질·네트워크 인지 오케스트레이션: 첫 검증 계획

작성일: 2026-10-23. 상태: **이기종 실행 후보 검증·설계 진행, 본 비교 미실시**. [문제 정의](problem-definition.md)가 현재 기준이다. [이전 계획](workflow-placement-experiment-plan.md)의 실측·재현 규칙은 재사용하되 주 목표와 우선순위는 이 문서를 따른다.

CPU·GPU·NPU를 포함한 원래 범위를 유지한다. 모든 보유 노드와 가속기 계열을 후보 검증 표에 남긴다. 특정 모델·런타임의 실패는 그 조합의 증거이며 가속기 계열 전체를 편의상 제외할 근거가 아니다. CPU 전용 진단은 기준선 개발에 활용할 수 있으나 이기종 본 실험을 대체하지 않는다. 모든 단계가 모든 장치에서 실행되어야 한다는 뜻은 아니며, 각 단계의 실행 가능한 후보와 불가능/미검증 조합을 구분한다.

VQA(ResNet18 영상 특징·Wav2Vec2 음성 인식·MUTAN 결합)는 현재 서비스 후보다. CPU 진단 수집기는 구현됐지만 `qnv-20261023t073121`은 준비 Pod 미배정으로 추론 없이 종료됐다. 기존 60개 reference 출력 재채점은 보정 0.515/평가 0.355이며 탐색 문턱 0.40을 평가 집단이 충족하지 못했다. 평가 결과를 보고 문턱이나 입력을 바꾸지 않고 품질 문제를 별도로 해결한다.

## 1. 실험 시작 전 결정할 계약

| 항목 | 고정할 내용 | 현재 상태 |
|---|---|---|
| 서비스 | 영상·음성의 의미 있는 결합, 최종 응답/이벤트, 요청 단위와 시간 정렬 | VQA를 현재 구현 후보로 선정; 품질 미달 해결 필요 |
| 정답 데이터 | 최종 출력 라벨, 단계별 라벨의 가용성, 데이터 라이선스·버전·hash | 기존 60쌍 진단 fixture; 본 독립 평가 자료 미확정 |
| 모델과 결합 | 동일 모델·가중치·정밀도·전처리·결합 규칙으로 시작 | ResNet18·Wav2Vec2·MUTAN; 가속기 파생 산출물 검증 진행 |
| 품질 | 최종 accuracy/F1 등 서비스 지표와 문턱, 집단·누락 처리·불확실성 보고 방식 | 본 평가 전 동결 |
| SLO | 발생부터 최종 응답까지 deadline, 요청 집단별 차이 여부 | 본 평가 전 동결 |
| 자원 | 사용 노드·CPU/GPU/NPU·메모리·동시성, 서버 포함 여부 | 모델별 실행 검증 후 동결 |
| 부하·네트워크 | open-loop 도착 trace, 입력 구성/크기, 실제 경로와 공유 병목, 통제 조건 | 파일럿 후 본 평가 전 동결 |
| 분석 | 실질적 최소 개선, 반복 단위/수, 측정 길이, 정책 순서, 집계 규칙 | 파일럿 변동성 확인 후 동결 |

검증 가능한 정답·결합 의미가 없는 서비스는 성능 실험을 먼저 크게 실행하지 않는다. 특정 데이터셋이나 모델을 장비 지원 여부만 보고 선정하지 않는다. 품질 보정 자료와 최종 평가 자료를 분리하고, 같은 영상/세션의 유사 요청이 양쪽에 섞이는 누출을 방지한다.

## 2. 단계별 실행

### A. 고정 모델 실행 후보와 품질

1. 영상/음성 전처리·추론·결합의 입출력 계약을 정한다. 두 분기는 요청 ID와 입력 시간으로 결합한다.
2. 각 노드×가속기×런타임에서 실제 장치·fallback·연산자·dtype·shape·산출물 hash·peak 메모리를 검증한다.
3. CPU reference 수치 일치 검사와 정답 기반 단계/최종 서비스 품질 검사를 분리한다. 최종 품질은 파이프라인 전체 실행으로 평가한다.
4. 프로파일 수집 조건(스레드, warm/cold, 동시성)을 기록하고 실제 payload bytes·직렬화·복사·전송·실행·대기를 측정한다.
5. 보정 결과로 후보와 품질 기준을 동결한다. 평가 결과를 보고 어려운 입력을 제외하지 않는다.

통과 조건: CPU·GPU·NPU의 실제 실행 증거가 있고 복수 Task의 위치를 선택할 수 있을 것, 필요한 데이터셋에서 품질 기준을 충족할 것, 모든 실행 경로의 모델/입력/출력을 추적할 수 있을 것. 장치 등록·모델 변환 성공·단일 입력 실행·데이터셋 품질 통과는 각각 별도 상태로 기록한다. 미지원 조합은 오류와 산출물 근거를 보존하고, 미검증 조합을 미지원으로 바꾸지 않는다. 후보가 부족하면 변환·런타임·모델 지원 문제를 해결하며, 해결 전에는 이기종 본 실험이 미완료임을 명시한다.

### B. 동일 품질에서 네트워크·부하 효과

동일 입력 trace를 각 정책에 제공하며 저부하·포화 접근·과부하와 네트워크 조건을 조합한다. 전체 조합을 무조건 실행하지 않고, 사전 파일럿으로 범위를 정한 뒤 본 평가 조건을 동결한다. 빠른 응답이 다음 요청 발생을 촉진하는 closed-loop만으로 처리량을 비교하지 않는다.

- 정책: 실제 kube-scheduler 운영 구성, Task-fastest, 통신 인지 greedy, DAG 공동 선택, 선택기에서 통신비용만 제거한 ablation.
- 같은 모델·품질 후보·노드/자원·큐 한도·스케줄링 정보·데이터 표현을 사용한다. Kubernetes의 Pod 배치와 요청 라우팅의 차이를 명시한다.
- 공유 병목·큰 입력뿐 아니라 고대역폭·작은 입력·연산 지배 조건도 포함한다.
- 큐·동시성·드롭·재시도·batching·복제 설정을 고정하여 배치 효과와 구분한다.
- 정적 현재 정보 비교 뒤에 상태 갱신을 추가한다. 실제 온라인 관측과 사전 regime별 비용표를 준 이상 정보 대조를 구분한다.

통과 조건: 전체 유입 요청의 terminal 상태 또는 명시적 미완료가 남고, 서비스 품질·goodput·coverage·실패를 같은 조건별로 산출할 수 있을 것. 이득이 없거나 greedy와 같은 배치를 고르면 그대로 보고한다.

### C. 품질 제약의 효과

먼저 고정 모델에서 품질 필터의 영향이 실제로 있는지 확인한다. 모두 통과하고 선택이 같으면 이 단계의 결과는 차이 없음이다. 필요한 경우 검증된 정밀도/모델 변형을 추가하되 B의 고정 모델 결과와 합치지 않는다.

같은 선택기·실행 가능한 전체 설정 집합에서 품질 제약만 켜고 끈다. 기술적 호환성·메모리·자원 한도는 양쪽에 적용한다. 품질 미달 설정은 품질 제거 ablation에서만 실행 가능한 대조군으로 표시하며 서비스 요구조건을 만족한 후보로 부르지 않는다. 각 조건에 최종 품질과 goodput을 나란히 보고한다. 품질 미달의 높은 처리량은 동일 품질 개선이 아니다.

모델/정밀도를 바꾸면 compute·payload도 바뀔 수 있으므로 순수 배치 개선과 공동 설정 선택 개선을 따로 보고한다. 평가 정답을 보면서 요청별 모델을 고르지 않는다.

### D. 근접 선행과 전체 비용

[문헌 대조](quality-network-orchestration-related-work.md)를 바탕으로 품질·목적함수·다단계 실행 계약이 가까운 방법부터 선정한다. 원 구현 재현과 아이디어 이식/목적함수 변경을 구분한다. 기존 DAG 재최적화·단순 hysteresis에도 같은 최신 정보를 제공한다. Koordinator·기존 DRL은 이전 비교 계획을 이어가되 적합성·구현 범위·학습/추론 비용을 먼저 명시한다.

프로파일 획득·관측 나이·최적화·준비·전환을 포함한 전체 구간과 정상 상태를 나눠 보고한다. 배치 변경은 요청/Task 경계부터 시작하며, 실제 이익이 확인되기 전에 새 학습 예측기·복잡한 정책을 추가하지 않는다.

## 3. 필수 산출물과 집계

- 동결 manifest: 데이터 분할/요청 trace·모델/산출물 hash·실행 설정·품질 기준·SLO·자원·정책 버전·프로파일 시각·관측/전환 규칙.
- 요청 로그: 예정/실제 발생·수락·최종 응답 시각, deadline, 계획 버전, 정답/출력 참조, 오류/거절/드롭 사유. 발생기 미전송과 서비스 거절은 구분한다.
- stage 로그: 부모 요청 ID, 실제 실행 노드/장치·큐·실행·전달·bytes·준비·재시도. 병렬 분기·중첩 RPC를 중복 합산하지 않는다.
- phase 로그: 시작/종료 event, timeout의 부분 stdout/stderr, 설정 적용/복구와 소유 자원 정리 근거.
- 지표: 문제 정의의 유입 cohort 기준 goodput, 전체 유입 대비 기한 내 완료율, 최종 품질·coverage, p50/p95/p99, 실패/드롭/시간 초과/미완료, 큐·자원·관측·선택·전환 비용.

최종 상태는 요청당 하나로 집계하고 재시도를 독립 요청으로 세지 않는다. deadline 이후 성공은 완료 처리량에는 포함할 수 있으나 goodput에는 포함하지 않는다. 측정 종료 시점의 미완료를 삭제하지 않고 정해진 추적 종료 규칙을 적용한다. 품질의 집단별 분모와 미반환 처리를 공개한다.

같은 계획·같은 실행 조건이면 중복 실행을 독립 표본으로 늘리지 않는다. 부하·큐·적응 경로가 다르면 단순히 계획이 같다는 이유만으로 관측을 공유하지 않는다. 정책 순서/시간대의 영향을 통제하고 반복 run을 비교 단위로 둔다. 같은 host의 Pod 재배포는 driver/OS cache까지 독립인 반복이 아니다. 반복 수와 MDE는 파일럿 뒤 `statistical-power`로 별도 결정한다.

## 4. 첫 판단 기준

첫 산출물은 서비스 계약과 고정 모델 후보표다. 이어 동일 품질의 부하×네트워크 비교에서 병목과 이득/반례를 확인한다. 품질 인지·통신 인지·전체 시스템 효과를 각각 분리해 설명할 수 있고, 가까운 기존 방법과 단순 보완 이후에도 차이가 남는지를 확인한 뒤 논문 기여를 확정한다. 현재 VQA 후보의 가속기 검증과 서비스 품질 문제, 본 독립 평가 계약이 남아 있어 본 실험 실행 준비 완료 상태가 아니다.

## 5. 이기종 실행 설계와 현재 작업

구체 실행 구조·배정·완료 기준은 [이기종 시스템 설계](quality-network-heterogeneous-design.md)를 따른다. [전체 장비 감사](quality-network-heterogeneous-capability-audit.md)는 12개 노드를 보존하며 현재 등록/점유와 과거 모델 실행 증거를 분리한다. VQA의 탐색용 Qmin 0.40, SLO 2초, 기존 20/40 분할은 진단 계약이며 본 논문의 품질/표본 계약을 확정한 것이 아니다. 과거 평가 결과를 알고 있으므로 새 독립 holdout으로 부르지 않는다.
