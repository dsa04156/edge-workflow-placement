연구 목표: **품질·네트워크·이기종 실행환경을 고려해 AI DAG의 실행 위치를 선택하고, 품질 조건을 만족하는 유효 처리량을 개선한다.** 여기서 유효 처리량은 같은 자원과 사전에 정한 서비스 품질 기준 아래 기한 내 최종 응답을 완료한 요청 수/초다. 품질은 사전에 정한 데이터 집단에서 검증하며, 개별 요청의 정답을 보장한다는 의미가 아니다. 2026-10-26 사용자가 재확인한 목표이며, 아래 기존 방법 우선 검증은 이 목표를 위한 첫 단계다.

## 목적과 판단 순서

같은 CPU·GPU·NPU 자원과 최종 서비스 품질 요구조건에서, 기존 배치·실행 방법의 기한 내 완료 처리량이 어떤 조건에서 낮아지는지 확인한다. 기존 방법에 최신 관측과 단순 보완을 제공한 뒤에도 남는 손실이 있고 그 원인이 재현될 때 해결 방법을 설계한다. 새 알고리즘의 필요성이나 우월성은 가정하지 않는다.

실행 순서는 **비교 계약 → 공통 DAG 실행기와 기존 정책 → 기존 방법 실험 → 원인 분리와 단순 보완 → 제안 설계 → 독립 비교**다. 이 문서는 이전 계획의 실측·보존 규칙을 유지하며, 근접 선행 비교를 제안 방법 설계보다 앞으로 옮긴다.

## 현재 출발점

2026-10-23의 NPU 영상 + GPU 음성 + CPU 결합 60건은 실제 고정 배치 실행 증거다. 품질 점수 0.355는 탐색 기준 0.40에 미달했다. DAG 공동 배치의 유효 처리량 비교나 모든 장비 검증이 끝난 상태가 아니다. 60개 입력은 이미 관찰한 진단 자료이며 최종 독립 평가에 재사용하지 않는다. 2026-10-26 장비 가용성은 새로 확인해야 한다.

12노드와 CPU·NVIDIA GPU/Jetson·Intel/Hailo/Mobilint/Rockchip NPU의 후보 검증 범위를 유지한다. 첫 비교에도 실제 CPU·GPU·NPU가 포함된 실행 가능 후보를 제공하고, 복수 Task가 복수 위치에서 실행될 수 있어야 한다. 개별 정책이 일부 장치를 선택하지 않는 것은 결과다. 특정 장치를 쓰도록 강제하지 않는다. 점유·SDK 부재·변환 실패·실행 실패는 조합별 미완료로 남기고 전체 계열을 제외하지 않는다. 모든 미완료 장치의 복구를 기다리며 이미 가능한 비교까지 멈추지는 않는다. 사용한 장비 집합과 결론의 적용 범위를 매 실행에 명시한다.

## 1. 비교 계약과 서비스 품질 확보

두 작업을 함께 진행한다.

- 서비스: 영상 전처리 → 영상 추론, 음성 전처리 → ASR, 두 결과 → 결합의 5-Task DAG. 입력은 엣지에서 발생하고 최종 응답까지 요청 하나로 계측한다. 영상·음성 분기는 의존성이 허용하는 실제 동시 실행을 지원한다.
- 품질: 현재 VQA의 전처리·음성 인식·결합/모델 문제를 개발 자료에서 진단한다. 정답 질문 텍스트 등 진단용 대조는 원인 구분에만 쓰며 실제 ASR 경로와 바꿔 본 성능으로 보고하지 않는다. 모델/설정 변경은 새 버전과 품질·성능 재보정으로 다룬다.
- 데이터: 개발·후보 보정·최종 평가를 영상/세션 기준으로 분리한다. 독립 최종 평가 자료의 정답은 정책·모델 선택에 사용하지 않는다.
- 계약: Qmin, 품질 집단/누락 처리, SLO, 동시성·큐·재시도·드롭 규칙, 자원 예산을 본 비교 전에 동결한다. 기존 Qmin 0.40 및 SLO 2초는 진단 계약으로 보존하며, 결과에 맞춰 낮추거나 늘리지 않는다. 본 서비스 요구조건의 근거를 별도로 기록한다.
- 품질의 측정 단위는 완전한 파이프라인 구성/사전 요청 집단이다. 장치별 고정 정확도나 단계 정확도의 곱을 사용하지 않는다. 수치 parity는 별도 진단이다.

품질 개선 중에도 실행기·정책 연결 및 탐색 성능 실험은 진행한다. 단, 품질 미달인 성능 결과는 진단으로 표시하고 같은 품질에서의 개선 주장에는 사용하지 않는다.

완료 산출물: 서비스/데이터 계약, 장치별 실행 후보표, 최종 품질표, 미완료 조합과 오류 근거.

## 2. 공통 DAG 실행기와 기존 정책 연결

모든 정책은 같은 실행기·입력 trace·가용 후보·품질 증거·자원 예산·관측 데이터에 연결한다. 전처리 분리 전후의 품질 보존, 실제 payload 전송, 병렬 분기와 합류, 큐·장치 경합, 요청별 계획 버전, timeout/드롭/재시도 기록을 검증한다. 원격 RPC의 중첩 시간을 합산해 종단 지연을 만들지 않는다.

| 비교군 | 역할과 구현 계약 |
|---|---|
| 고정 이기종 배치 | 현재 실행 근거를 재사용하는 대조군. 제안 방법 아님 |
| Task-fastest-feasible | 동일 품질 적격 후보에서 단계별 실행시간 위주 선택; 공동 결정 효과 분리 |
| 통신 인지 greedy | 같은 관측으로 연산·큐·전송을 반영하는 단순 보완 대조 |
| 기존 DAG 배치 | 정적 계획과 현재 관측으로 재최적화하는 버전 모두 포함 |
| 재최적화 + hysteresis | 작은 변화에 반복 전환하는 비용을 단순 보완으로 해결 가능한지 확인 |
| 근접 선행 정책 | JellyBean·OctopInf를 우선 구현 적합성 감사; Atlas·AnchorDL은 가정/본문/코드 확보 수준에 맞춰 비교 계약 작성 |
| Kubernetes/Koordinator·기존 DRL | 기존 비교 범위 유지. Pod 배치와 요청 라우팅의 결정 단위를 구분하고 설정·학습/추론 비용 명시 |

위 논문명은 비교 후보이며 재현 성공을 뜻하지 않는다. 첫 단계에서 원문 버전·공식 코드 revision·목적함수·입력 정보·결정 단위·backend 적응 범위를 표로 확정한다. 최소한 품질/워크플로 선택과 네트워크/실행 제어에 가까운 선행을 각각 대조한다. 확보하지 못한 코드는 미완료로 표시하며, 임의 greedy를 해당 논문 이름으로 부르지 않는다. 원 구현 재현과 공통 실행기에 이식한 정책 결과는 분리한다. 원 시스템의 batching/복제 등 고유 기능을 제한했다면 정책 비교의 범위로 한정하고 전체 시스템 우월성으로 해석하지 않는다.

작은 DAG의 정확 열거는 예측 비용 모델의 선택 검산용이다. 실제 온라인 goodput의 상한 또는 신규 알고리즘으로 부르지 않는다.

완료 산출물: 정책 재현/이식 계약표, 실제 선택 배치, 후보·정보·자원 동일성 검증, 실행기 추적 로그. 공통 실행기는 측정 도구이며 아직 제안 기여가 아니다.

## 3. 기존 방법에 대한 실험

정책별로 같은 절대 도착률의 open-loop trace를 사용한다. 파일럿으로 조건 범위를 고른 뒤 본 비교 전에 동결한다. 다음 단계를 순서대로 실행하며 처음부터 전 조합을 곱하지 않는다.

| 실험 | 바꾸는 조건 | 질문/산출물 |
|---|---|---|
| E1 정적 네트워크 × 부하 | 양호/제한 네트워크, 저부하/포화 근처/과부하 | 기존 방법별 goodput 곡선, 병목과 선택 배치 |
| E2 비용 원인 분리 | 실제 입력·중간 표현 크기, 동시성/경합; 나머지 고정 | 연산·대기·전송 중 손실 원인과 이득 없는 조건 |
| E3 동적 변화 | 네트워크 변화, 별도 자원 경합 변화, 변화 지속시간 | 정적 계획 vs 재최적화 vs hysteresis의 전체 구간 순이익 |
| E4 정보/전환 비용 | 동일한 관측 갱신 주기·지연, 모델 준비/전환 상태 | 최신 정보 부족인지 정책 문제인지, 단순 보완 후 잔여 손실 |
| E5 품질 제약 | 동일 선택기에서 품질 제약 on/off; 검증된 설정 변형 | 실제 품질·속도 trade-off와 제약의 효과 |

E1은 고정 모델/검증된 품질 후보부터 시작한다. 모든 후보의 품질과 선택이 같으면 품질 인지 효과는 차이 없음이다. E5에서 필요한 모델·정밀도 변형을 추가할 경우 새 보정·품질 검증 후 별도 실험으로 보고한다.

네트워크 제한은 실측된 애플리케이션 경로/공유 gateway 제어부터 사용한다. bandwidth·지연·경로를 검증하고 물리 링크 변화와 구분한다. 토폴로지와 서버 source를 바꾼 값을 엣지 source와 합치지 않는다. 실제 작은 데이터/고대역폭/연산 지배 반례도 포함한다. 주 비교에는 현재 관측만 제공하고 사전 regime 정보/미래 trace를 준 대조는 별도 이상 정보 실험으로 표시한다.

## 4. 결과 판단과 제안 방법 설계 조건

첫 결과물은 **정책 × 조건의 품질·goodput 표, 자원/네트워크/대기 시간 분석, 선택 배치, 실패·드롭 내역**이다. Task-fastest보다 좋다는 결과만으로 새로운 연구 기여를 확정하지 않는다.

1. 차이가 실행기 오류·CPU fallback·품질 차이·다른 자원 예산에서 생겼다면 수정 후 해당 조건을 재검증한다.
2. 같은 최신 관측을 준 기존 재최적화나 단순 hysteresis로 차이가 사라지면 그 결과를 채택한다.
3. 통제된 반복에서도 잔여 손실이 있고 기제가 확인되면 그 원인에 필요한 최소 방법을 설계한다. 예: fan-in 경로와 공유 장치 큐의 결합, 준비/전환 비용과 변화 지속시간의 상호작용은 검증할 가설이며 현재 사실이 아니다.
4. 잔여 손실이 없다면 새 알고리즘의 필요성을 주장하지 않는다. 검증한 조건의 결과와 연구 질문 수정 근거를 남긴다.

제안 설계 후에는 같은 강한 기준선과 비교하고, 품질 제약 제거·네트워크 항 제거·새 메커니즘 제거를 분리한다. 탐색에 쓰지 않은 입력/변화 trace로 평가한다. 고정 모델 배치 이득과 모델/정밀도 선택 이득을 분리한다.

## 5. 지표와 반복 계약

- 주 지표: 동결한 유입 구간의 요청 중 deadline 이내 최종 응답 완료 수 / 유입 구간 길이. 요청의 마지막 deadline까지 추적하고 drain 시간을 분모에 임의 추가하지 않는다. 분기 결과와 재시도를 독립 요청으로 세지 않는다.
- 품질 하한 통과 여부를 goodput 옆에 별도 표시한다. 미달 정책은 동일 품질 비교의 적격 결과가 아니다. quality × goodput의 임의 곱으로 대체하지 않는다.
- 보조 지표: 최종 서비스 품질, 출력 coverage, 누락을 반영한 전체 유입 품질, 전체 유입 대비 기한 내 완료율, 완료 지연 p50/p95/p99, 실패·드롭·기한 초과·미완료·발생기 미전송, 관측/선택/전환 비용.
- 쉬운 요청만 남기는 효과를 확인하도록 반환/기한 내 반환/전체 유입 집단의 품질과 coverage를 구분한다. 요청별 정답 보장으로 해석하지 않는다.
- 동일 입력·도착 trace를 run/block으로 짝지어 비교하고 정책 순서를 균형 배정한다. 요청 수를 독립 반복 수로 사용하지 않는다.
- 파일럿의 run 간 분산으로 최소 의미 효과와 필요한 반복 수·측정 길이를 본 비교 전에 정한다. 수치 확정은 statistical-power 절차로 수행하며 임의 반복 수로 유의성을 선언하지 않는다.
- 효과 크기와 반복 단위의 신뢰구간, 이득 없는 조건을 함께 보고한다. 이미 결과를 본 뒤 유리한 조건만 주 결과로 선택하지 않는다.
