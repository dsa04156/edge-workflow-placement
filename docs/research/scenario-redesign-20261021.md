# 실제 DAG에 연결한 시나리오 재설계 초안

2026-10-21. 상태: 근거 검토·설계 초안. 새 구현·수집 없음. 후속 진행 요청에 따라 최신 정적 범위를 유지한다.

후속: [실제 DAG의 측정 항목·배치 경로 대응 계약](actual-dag-measurement-contract-20261021.md)에서 두 조건 각 19개 배치의 비용식 일치를 확인했다. 품질 검증에서 얻는 초기 연산 관측과 실행 가능성으로 제거할 probe를 비교 계약에 반영했다.

## 범위 정정

[최신 실측 보고](../experiments/budget-completion-20261021.md)는 사용자 결정에 따라 동적 재배치를 논문 범위에서 제외한다. 앞서 동적 시나리오를 제안한 설명은 이전 문제 정의에 의존했고 이 결정을 놓쳤다. 이 문서는 기존 결정을 바꾸지 않는다. 아래 정적 설계는 최신 범위에 맞춘 안이며, 동적 확장은 별도 선택 사항이다.

또한 [현재 알고리즘 설계](decision-focused-placement-design-20261021.md)의 대상은 **정적 배치를 선택하기 위한 측정 순서와 종료**다. 배치 탐색 알고리즘의 우수성, 온라인 재배치의 우수성과 구분해야 한다.

## 확인한 사실과 기존 시나리오의 문제

- 실제 시스템은 E0 이미지 → V(ResNet18), E1 음성 → S(Wav2Vec2), 두 결과 → F(MUTAN)의 fork/join이다. 세 작업은 CPU 검증 상태이며 서버 C의 작업 슬롯 2개는 연구용 admission budget이다.
- 동결 run `wan-20261021t044624`에서 10Mbps는 greedy C/C/E0, 정확 열거와 한 번 교환은 E0/C/C다. 2Mbps에서는 네 정책 모두 E0/C/C다. 따라서 두 WAN 조건은 **정확 열거의 최선 배치가 바뀌는 실증 사례가 아니다**.
- 10Mbps의 greedy 대비 개선은 한 번 교환으로 전부 해소됐다. 새로운 배치 탐색 알고리즘이 필요하다는 근거로 쓰지 않는다.
- 합성 v2의 임의 비용식·독립 관측 스트림은 규칙 검증에는 유효하지만 실제 작업, 전송 경로, 프로파일 취득 비용에 대한 대응 관계가 부족하다. 이름을 바꾼 사례는 독립적인 환경 다양성이 아니다.
- 동결 p75 요약값만으로 새로운 순차 측정 표본이나 i.i.d. 성질을 만들 수 없다. 실제 공유 경로의 서로 다른 payload 전달 시간을 하나의 동일 primitive로 합치는 것도 정당화되지 않는다.

근거 파일: `artifacts/topology-profile-live/wan-20261021t044624/{design.json,plans-frozen.json,profile-calibration-10.json,profile-calibration-2.json}`. 해당 profile은 isolated compute와 payload echo/control RPC proxy이며 queue/contention 예측이 없다고 명시한다.

## 정적 연구를 유지할 때의 실험 질문

**같은 실제 DAG, 실행 가능 배치, 목표 정확도에서 전체 프로파일링이나 단순 선택 측정보다 측정·계획 시간을 줄이면서 실제 배치 성능을 유지할 수 있는가?**

고정할 것은 모델·산출물·품질 기준·입력 source·자원 제약이다. 매 실험 episode 안에서는 네트워크 조건을 고정한다. 조건 사이의 차이는 정적 환경 비교이며 온라인 적응 결과가 아니다.

| 시나리오 | 만드는 방법 | 판별할 것 |
|---|---|---|
| 실제 10Mbps 기준 조건 | 기존 구성을 새 보정·새 평가로 반복 | 한 번 교환으로 충분한 환경에서도 선택적 측정의 추가 이득이 있는가 |
| 실제 2Mbps 일치 대조군 | 기존 구성을 그대로 유지 | 정책 배치가 같은 쉬운 조건에서 불필요한 측정·계획 비용만 늘리는가 |
| 배치 차이가 작은 조건 | 개발용 물리 조건 sweep으로 먼저 탐색하고 평가 전에 동결 | 작은 차이를 구분하느라 절감분을 소모하는가; 그런 조건을 못 찾으면 부재도 보고 |
| 지배적인 분기가 다른 조건 | 실제 입력 길이·크기 또는 검증된 자원 설정을 바꾸고 품질·비용을 재보정 | fork/join 임계경로 변화가 측정 선택에 실제 영향을 주는가 |
| 취득 비용 차이가 큰 조건 | probe별 준비·실행 wall time을 직접 측정 | 비싼 probe를 피하다 잘못된 배치를 선택하는가 |
| 상관·간섭 진단 | 기존 시간순 원시 기록으로 우선 진단; 추가 간섭은 별도 설계 | 비용모형·통계 가정이 깨질 때 proxy 인증과 실제 결과가 얼마나 어긋나는가 |

하단 네 행은 발견·검증할 후보이지 이미 존재하는 실측 결과가 아니다. 원하는 알고리즘이 이기는 조건만 남기지 않는다. 입력 변경은 실제 작업량·출력 품질 변화를 동반하므로 가상의 tensor padding이나 독립 비용 배율로 대체하지 않는다.

## 실제 DAG와 수학 모형 연결

V와 S는 병렬이고 F는 두 결과 도착을 기다린다. 개념식은 다음과 같다.

\[
L(p)=\max\{T_{E0\to V}+C_V+T_{V\to F},\;T_{E1\to S}+C_S+T_{S\to F}\}+C_F+T_{F\to E0}.
\]

이는 비용 경계를 설명하는 식이다. 실제 실행기의 control RPC, 시작 시차, 반환 경로를 확인하여 원래 목적함수와 대응시킨 뒤 사용한다. 중첩 RPC를 더하거나 병렬 두 분기를 합산하지 않는다. primitive p75를 이 식에 대입한 값은 실제 E2E p75가 아니다.

후속 구현의 첫 산출물은 임의 p/q/r 비용식 대신 다음 대응표다: `primitive ID → task/경로/payload/관측 필드/단위/공유 조건/취득 절차/준비 비용`. 각 실행 가능 배치의 경로식은 동일 대응표에서 생성하며 기존 planner와 전수 비교한다. 실행 가능 집합은 CPU·메모리·슬롯·품질 제약에서 다시 생성한다. 모든 3³ 조합이 가능하다고 가정하지 않는다.

## 비교와 평가 계약

1. **측정 선택 비교:** 전체 균등 측정, 순환 측정, 공통 가산항 제외 순환, 폭/비용, incumbent–witness, 후보 contrast 규칙. 같은 배치 후보·관측 권한·종료 인증을 사용한다. probe 개수뿐 아니라 동일 wall-time 예산에서도 비교한다. 전체 측정 대조군의 사전 고정 표본 수와 종료 기준을 명시한다.
2. **배치 정책 비교:** 같은 완성된 비용표에서 greedy, HEFT 변형, 한 번 교환, 교환 후 한 작업 이동, 정확 열거를 별도로 대조한다. 정확 열거는 작은 문제의 모형 기준해다. 측정 규칙 효과와 배치 규칙 효과를 한 표의 단일 원인으로 해석하지 않는다.
3. **평가 분리:** 개발용 조건 탐색 → 규칙·조건·예산 동결 → 별도 취득 episode → 별도 실제 종단 평가. 기존 evaluation split 7–12 재사용은 새 holdout으로 부르지 않는다.
4. **반복 단위:** 전체 취득·선택 episode를 단위로 하고 host/day/load 상태로 블록화한다. episode 내부 요청이나 정책이 공유한 배치 관측을 독립 반복으로 세지 않는다. 정책 순서·배치 평가 순서를 무작위화하고 cache carryover를 기록한다.
5. **결과:** 취득·준비·계획의 실제 elapsed time, 선택 배치, proxy gap/인증 여부, 별도 E2E 성능, 실패·timeout을 모두 남긴다. 실패 표본을 제외한 성공 평균만으로 우수성을 판정하지 않는다. 겹친 시간을 중복 합산하지 않는다.
6. **소표본 경계:** 기존 두 블록·배치당 6요청은 검정력 근거가 아니다. 실질적인 시간 절감 및 성능 유지 허용치를 먼저 정하고, pilot의 episode 간 분산으로 필요한 반복 수를 결정한다. 숫자·실행 순서가 동결되기 전에는 실행 가능한 최종 프로토콜로 표시하지 않는다.

## 진행·중단 기준

먼저 실제 비용표와 실행기에서 primitive/경로 대응을 검증한다. 오프라인 replay는 개발 진단이며 새 실측이나 순차 통계 보장으로 보고하지 않는다. 시간 상관이 남는 실제 trace에 합성 i.i.d. DKW 보장을 그대로 적용하지 않는다.

후보 규칙의 총 시간 절감이 단순 기준선보다 작거나, 실제 배치 성능을 유지하지 못하거나, 3Task 규모에서 전체 측정 자체가 충분히 싸면 새 방법의 실용적 필요성이 확인되지 않은 것으로 결론 낸다. 간단한 공통항 제외나 witness 규칙이 충분한 결과도 남긴다.

## 동적 범위를 다시 열 경우에만 추가할 계약

먼저 실제 보정에서 최선 배치가 달라지는 두 환경을 찾아야 한다. 현재 10/2Mbps만으로 그 조건이 충족되었다고 말할 수 없다. 그 다음 관측 획득·지연, 전환 준비, 중단·실패·재시도, 변화 지속시간을 포함한 전체 episode를 설계한다. 동일 최신 정보를 준 재최적화와 현실적인 관측 정책을 분리하고 hysteresis를 비교한다. 비정상 환경에 현재 고정 분포 인증을 재사용하지 않는다. 이 확장은 현재 정적 결과에 소급 적용하지 않는다.

## 설계 절차 출처

블록화, 실제 실험 단위, carryover, 사전 고정 순서 설계에는 로컬 `experimental-design` 스킬을 적용했다. 해당 절차 라이브러리의 출처는 Kassis et al. (2026), [Scientific Agent Skills: A Library of Procedural Knowledge for Research Agents](https://doi.org/10.48550/arXiv.2609.00065)다. 이는 엣지 배치 알고리즘의 효과나 신규성에 대한 근거가 아니다.
