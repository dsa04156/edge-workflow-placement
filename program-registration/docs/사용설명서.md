# 사용설명서

## 준비

Python 3.9 이상과 표준 라이브러리를 사용한다. 모델 파일·GPU·kubectl·외부 패키지는 로컬 계획 계산에 필요하지 않다. 명령은 패키지 루트에서 실행한다.

## 배치 계획

```bash
python3 src/prepare.py --config examples/measured-compressed-2.json --policy topology_profile --run-id edgeflow-demo --out output-plan
```

정책은 `topology_profile`(연산+전달), `profile_only`(연산만), `topology_only`(노드별 연산 차이를 평균화), `resource`(실제 노드 선택은 default-scheduler에 위임)다. `resource`는 자원 점수 시뮬레이터가 아니며 계획의 placement는 null이다.

입력 JSON은 `nodes`, 위상 순서의 `tasks`, `outputs`를 포함한다. 각 작업은 실행 후보, 후보별 `compute_ms`, CPU·메모리 요청과 입력 간선별 `transfer_ms`가 필요하다. 전달 키는 `출발노드|도착노드`이며 동일 노드 경로도 포함한다. `provenance=measured`와 `evidence_id`는 입력 메타데이터 계약이며 프로그램이 원격 측정값의 진위를 인증하는 것은 아니다.

예제에는 과거 실험의 실제 노드명·자원 snapshot·이미지명이 들어 있다. 다른 환경에서는 새 측정과 노드·namespace·이미지·실행 command 설정이 필요하다. 생성된 Pod 명세만 적용한다고 원래 AI 워크플로가 재현되지는 않는다. 패키지는 클러스터에 명세를 적용하지 않는다.

출력 `plan.json`의 예측값은 큐와 동시 링크/노드 경합을 제외한 비용표의 임계 경로다. 실제 관측 E2E와 구분한다. 조합 수100000 초과, 실행 가능 배치 없음, 입력 누락·순서 오류는 거부한다. 출력 폴더가 이미 있으면 덮어쓰지 않는다. run-id는 소문자로 시작하는 최대30자의 DNS형 이름을 사용한다.

## 관측 기록 집계

```bash
python3 src/analyze.py examples/observed-attempts.jsonl --out output-comparison.json
```

JSONL 각 줄은 run_id/request_id/condition/block/policy/warmup/status/quality_ok를 갖고, 성공·품질 통과 시 e2e_ms가 필요하다. 평균과 p95는 품질을 통과한 성공 요청에 한정한다. 실패·품질 불일치 개수와 분모를 함께 읽는다. 결과의 block 필드명이나 도구의 단위 문자열은 표본의 독립성을 인증하지 않으며 제공 예제는 단일 관측 블록이다.

## 검증

```bash
python3 -m unittest discover -s src -p 'test_*.py'
```

기존 승인 범위인 프로파일→계획/Pod 명세 검증과 결과 집계 회귀 검증을 재사용한다. 테스트 fixture는 합성 입력으로, `--allow-fixture`는 로컬 인터페이스 검사 용도다. 실제 성능 근거에는 실측 예제만 사용한다.
