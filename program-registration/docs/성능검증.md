# 성능 검증 근거

주 근거는 `wan-20261020t024540` 완주 실험이다. Pi2대+CPU서버에서 이미지 source E0·음성 source E1을 고정하고 ResNet18/Wav2Vec2/MUTAN을 실행했다. 평가54/54, 워밍업 포함72회·216receipt, 최대 score 오차1.9669532775878906e-6, 소유 리소스 잔여0이다. 이 패키지를 만들며 새 클러스터 실험을 실행한 것은 아니다.

| 조건 | 서버 집중 C/C/C | 결합 비용표의 선택 배치 | 관측 해석 |
|---|---:|---:|---|
| 제한 없음 | 220.11ms | C/C/C, 같은220.11ms | 선택 동일 |
| 100Mbps | 580.89ms | C/C/C, 같은580.89ms | 선택 동일 |
| 10Mbps | 668.97ms | C/C/C, 같은668.97ms | 선택 동일 |
| 2Mbps | 1271.25ms | E0/C/C,917.44ms | 평균27.83% 감소 |

C=CPU서버, E0=이미지 source Pi다. 제한 조건은 방향별20ms 추가 지연을 사용했다. 각 고유 배치6개의 평가 입력을 사용했고, 같은 배치는 같은 관측을 공유했다. 단일 블록 기술 통계이며 일반적인 성능 보장이나 유의성 결과가 아니다. greedy·HEFT도 결합 비용표와 같은 배치를 선택했으므로 정확 열거 자체의 우월성은 확인하지 못했다.

계획의 예측 지연은 보정 비용표 계산값이고 위 표는 별도 평가의 실제 E2E다. 패키지 예제 실행은 예측 계획 재생이며 모델 추론 성능 측정이 아니다. 실제 입력은 공개 이미지·음성 파일의 엣지 Pod 재생으로 실제 센서 수집 검증은 아니다. 정상 요청 지연은 배포·보정·재배치 비용을 포함하지 않는다.

후속 슬롯 제한 실험의10Mbps 첫 블록에서는 정확 열거가greedy보다16.80% 낮았지만 제어EOF로 전체가 미완료였다. 이 수치는 등록 프로그램의 주 성능 근거로 사용하지 않는다. 이전 보고서: https://github.com/dsa04156/edge-workflow-placement/blob/3bd5c34630eef5fde6da9a9d07a127642b033ce9/docs/experiments/greedy-joint-budget.md

`evidence/`에는 전체 완주 요약·감사와 주 비교12건 원본을 포함했다. 전체 감사의 원자료 전체·모델 bundle은 포함하지 않았으므로 여기서 기존 클러스터 감사를 전부 재실행할 수는 없다. 소스와 실측 예제의 출처는source-provenance.json을 따른다.
