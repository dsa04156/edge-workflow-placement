## Evidence and design decision (coordinator)

Reopt crosses server when predicted latency decreases even with ample 2s slack. b0-slow-dag_reopt switches at 1.57s and1.74s before degradation; at24.51s prediction324.1ms produced late_ok. b1-slow-hysteresis at24.31s prediction337.7ms led timeout. Existing generator.learn updates compute/link EWMA only after both branches return success; queue polling freshness is separate from link evidence freshness. These are code/trace observations, not causal isolation. New complex learning or model replacement is not warranted.

V1 policy dag_deadline_guard: freeze anchor = existing exact best_plan on startup profile, no observed queue. At each decision use the SAME live profile and queue model as dag_reopt to predict anchor. If anchor prediction <= deadline_ms * anchor_fraction, keep anchor. Otherwise run existing reoptimization and choose the lowest predicted makespan eligible plan (including anchor). Default deadline_ms=2000, anchor_fraction=0.75 (a priori engineering reserve, not tuned/optimized). Record anchor prediction, threshold, selected prediction, choice reason, and fallback. Retain inherited stale/no-success fallback to anchor and explicitly record that it has no freshness guarantee. No trace/time-phase oracle, no hardcoded edge/server/node preference, no GT/answer quality, no new request rejection. Returning to anchor is allowed immediately when its prediction is within budget. Acknowledge limitation: inaccurate live predictions can still hold a poor anchor or choose a bad alternative; this is an SLO-aware selection hypothesis, not a reliability guarantee.
